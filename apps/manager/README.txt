MeowGM 0.7.4 — 独立版本候选

启动直接进入本地管理界面，无需注册或登录本机 GM 账号。
在“连接设置”手动填写服务器 IP/域名、SSH 端口、用户名和密码，点击保存。
下次启动自动回填地址、端口和用户名。密码由 Windows 当前用户 DPAPI 加密保存，界面不显示明文；密码留空保留已存值。
保存不连接服务器、不执行远程命令。点击“连接服务器”才发起 SSH 连接。首次会显示主机 SHA256 指纹，在服务器控制台独立核对后填入并保存，再次连接；尚未核对时不发送密码。SSH 已连接只代表认证成功，115US 远程管理协议仍未完成。

本地环境：选择 115US 整合包根目录后，可只读查询符合上游结构的账号和角色。
运行状态未知时不会显示运行正常；不启动已冻结的 86S4A21。
MOD 安装、游戏启停、115US 远程写入未完成，不能据此版本进行完整生产验收。

数据仍保存在当前用户应用数据目录；重装前备份整个应用数据目录。
加密密码绑定当前 Windows 用户，复制到另一台电脑或另一 Windows 用户后需要重新输入。
软件只有一个 GM 版本。更新源需在 EXE 同目录 manager.public.json 显式填写 updateBaseUrl；未配置时不使用默认商业站点。

界面：直接复用 115us-dfolauncher 的独立 GM 窗口结构和样式，保留顶部账号/角色、角色属性与功能标签页。服务器连接、客户端发布和设置从右上角进入。上游写操作接口尚未接通的按钮为禁用状态。来源与提交见 apps/admin/UPSTREAM-UI.txt。

MOD 管理：右上角 MOD 管理入口支持本地 115US 已安装服务端 MOD 的读取、启用和停用，调用内置上游 modkit，保留依赖检查，配置写入后重新读取确认。已有 enabled.json 修改前备份。实际生效以近期服务端上报为准；安装/卸载与云端控制未接入。
游戏活动：右上角单独入口，目前未接通节日、副本、掉落的统一开启接口，状态未知，开关不可用。

本地 GM：工具 → 本地 GM 连接，填写包含 Script.pvf 的实际客户端目录并手动连接。连接前对现有 SQLite 存档做一致性备份并检查完整性；首次 PVF 解析可能较慢。保存配置不会自动连接。当前仅支持带 module dfolan 的本地源码包，云端与纯二进制包尚未适配。
技能点：选择账号/角色并连接本地 GM 后，角色页可读取技能点与回执、增加 SP/TP。填写原因并确认后才写入。流水号在发送前保存在本机，超时等失败保留原请求；连接原环境和原角色后可按原流水号重试。勿手动清除待核对流水，先查历史回执。
验证范围：原生 Go 桥接已通过合成 SQLite 角色读取、SP/TP、重复流水、冲突拒绝、回执与回滚测试。界面采用独立模拟通道测试。既有32dd PVF已在只读副本+合成SQLite通过初始化、角色读取、SP写入、重复流水和回执；实际玩家存档与游戏入场未验收，不能据此宣布完整 GM 可用。
双模式目标配置和大厅/左栏已接入；完整云端管理、新原生插件页、AI分析接口仍在开发；MeowLink未封包，无可验证正式下载。PVF保护模块缺失，只能读取大小和SHA256，不提供加解密能力。

0.7.2目标与导航：管理大厅和左栏分类可进入现有角色/连接/MOD/PVF/活动/控制台页面。通用和自定义各自保留本地/云端目标；切换只预览，点击保存才应用并断开原GM/SSH连接，不自动连接。旧environment.json在显式保存时迁移，保留原本地目标。云端根目录用Linux绝对路径；HTTPS管理源地址不得含密码、路径、查询或片段。当前无可用云端管理协议、认证或scope，保存目标不代表GM可用。SSH配置仍独立于四个目标槽位，切换后须人工核对，不使用数据库凭据。

有效PVF验证限制：已解析实际32dd源，但未复制ImagePacks2、未验证图像预览或游戏运行；缺refine.json时原生GM明确禁止锻造发放，4066项缺中文补译保留原名。这些能力不计为已完成。
升级到0.7.2后，管理器更新配置使用同目录manager.public.json中的updateBaseUrl，不再读取launcher.public.json；尚无正式更新服务验收。

0.7.3资源诊断：工具→本地GM连接中的资源诊断可读取所选服务端refine.json结构与SHA、ImagePacks2存在状态、本次原生GM的缺译/缺资源告警。存在不代表功能可用；锻造发放仍未开放。连接后输入物品ID可通过真实GM读取名称与PNG，失败显示原生错误，不生成占位图。已在32dd PVF及只读复制的sprite_item_stackable.NPK上验证物品10317909的原生图像，源NPK/规则哈希保持不变；不是全部图像或锻造/游戏实机验收。
0.7.3合成演练：服务控制台增加健康/日志/受控启停参考，只能启动固定内置合成进程，无网络监听、玩家库或游戏操作；不能填写命令/PID/路径。默认禁用，开发演练需在主机启动环境显式设置MEOW_GM_SYNTHETIC_CONTROL=1。退出管理器会清理自有worker，不是永久后台服务。此参考合同不是生产管理ABI，host尚无已冻结管理endpoint和权限合同，不能据此控制真实游戏服。

0.7.4内部键边界：GM界面/API中的native账号/角色键用规范正十进制int64字符串，后台校验后送原生Go整数接口；库内INTEGER和关系不改。拒绝前导零/符号/科学计数/浮点/超范围；旧数值输入仅兼容1..9007199254740991。已覆盖2^53±1/MaxInt64；大内部键的合成库原生读写和真实PVF界面链通过，UID与内部键不互转。
账号/UID存储由服务端显式选external或SQLite；GM不收DB广权凭据，不回退或迁移角色/背包。DB目前只有配置合同候选，external真实adapter及管理API尚未实现，不能据此版本宣称可接外部库。用户登录id为login_id、username只作昵称；GM不实现游戏账号注册/登录、不按昵称自动绑定，内部账号键不等于login_id/UID。

身份编辑边界：玩家的login_id与UID注册后不可自行改，username只作昵称；注册告知和玩家API强制约束由网站/宿主负责。GM未开放修改login_id/UID的接口或按钮。后台权限、冲突/保留号、审计及撤销机制准备好之前维持关闭；旧008/009回执不可原地UPDATE冒充新UID，须先冻结identity revision/superseding receipt合同。不会改当前用户ID、号池序列、native内部关联键或角色归属。
